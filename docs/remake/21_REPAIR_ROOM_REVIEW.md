# 修復室の本編接続と部分通し確認

P20〜22を本編へ接続。東書庫の戸を通り、雨窓の下で支持具を組み、南の光路と小口を操作し、北の板の覆いを外して戸を開けられる。奥の原型庫は現在、同じ座標の室内殻のみで、入室はまだ制作中の境界。ゲーム全体の完成ではない。

## 実操作で確認した範囲

P16を解いた中盤状態と必要材料から開始し、PC1440×1000とタッチ390×844で各67操作を実行。座標位置の実要素を確認してからクリック/タップした。持ち物が画面外へ続く場合だけ、一覧をスクロールしてから操作した。

- 書庫の戸口→修復室。移動方向を保った東向きの入室。
- 角当てと木片を使う支持具の組立、横からの確認、持出し。
- 光路の変更と留め棒の開放。
- 同じ支持具と六折の設置。取得順[0,1,4,5,2,3]を保ち、スロット順[5,0,3,1,2,4]へ本人の操作で並べ替え。
- 小口の絵と実物の拡大鏡。正解画像を別に見せず、現在の場面を拡大。
- 再読込み後も紙の順、支持具の所在、開いた留め棒を保持。元の机から支持具が消えていること。
- 覆いを紙ナイフで外し、隠し戸を開く・閉じる。
- 修復室側から書庫の戸を閉じる・開く→棚を避けた実際の空き幅から戻る。帰路は西向き。

別のタッチ確認では、誤った板の覆いも外して戻せること、小口の既読/solved22なしでも物理手順を知っていれば戸が開くこと、開扉の保存/再読込み/閉扉を確認した。これは作者の部分検証であり、独立した初見プレイや最初から最後までの通しではない。

## 修正した視覚上の欠陥

- 中央の板だけに黒い長方形の隙間が出て正解を示していた。実際の開口を木枠の内側へ収め、三枚の見え方を揃えた。
- 外した覆いが通路に立っていたため、脇の壁へ移した。
- 書庫の戸の裏面と厚みを追加し、両側から同じ戸を操作できるようにした。
- 小口の拡大でSVGの線が点線状に崩れた。Faceの実寸とラスタライズ密度を分け、紙面は12倍、拡大鏡使用時は24倍で描く。
- 小さい木板に出た黒い点は、写真の内部透過ではなかった（上部木面のalpha最小250以上）。平面縮小との比較で3D縮小時の再サンプリングと判明。投影後の大きさへ描画密度を合わせて改善。背後の物体は別途、実寸の奥行きで描画から除外している。

証跡は研究remake/qaのmain-repair-pc-*、main-repair-touch-*、repair-north-adaptive.png、repair-panel-adaptive-close.png。木板の初稿/黒点/失敗の画像を最終の採用根拠に混ぜない。115テスト通過。段階ヒントは現在状態と取得した原紙の並びから案内する。
