# 確認後の全室展開

受渡口の方式はユーザー確認済み。次の承認待ちは設けず、全編まで継続する。代表版の制作終了を全面改修完了と扱わない。

## 移行の契約

- `remake`ブランチ。第一チェックポイントは6fc9828。
- 旧版`App/Puzzles/engine`を本編画面として呼ばない。純粋な折り・合成・鍵の計算は個別検証して再利用できる。
- 部屋・向き・現物の状態・物品の所在を一つの保存モデルへ統合する。受渡口v2の進行を新しいモデルへ引き継ぎ、旧版v1は変更しない。
- 接写は場面全体を切り替える。同じ物・同じ台・同じ光を保持する。室内の機構は写真として生成し、操作対象は写真上の実物。
- 数字錠は写真に存在するドラムを触る。動的な数字も、写真の窓と遠近に合わせた印刷面として表示する。写真外の上下ボタンへ戻さない。
- 紙に印刷された図は正確な幾何から描けるが、紙の四隅・傾き・質感へ合わせる。紙自体をCSSの矩形に置き換えない。
- 戸は開いてからその戸口へ触れて通る。入室時の向きは通過方向を維持する。地図で戻る場合は訪問時の向きを復元する。
- 通路、灯り、設置物は「解決済み」だけでなく現在の物理状態から描く。

## 作業順

1. 帳場・校正室・搬出間の四方向と入口を、受渡口から見える写真を参照して制作。
2. 序盤P01〜07の写真内操作と、部屋間移動を接続して確認。
3. 活字・印刷・製本室P08〜15。同じ版・紙・糸・道具が別の場所でも一致することを確認。
4. 二つの書庫と修復室P16〜22。棚・床・通路の空間推理を平面盤面へ置き換えない。
5. 原型庫と終盤P23〜30。実物の本・端面・型・鍵で構成し、見本の解を転記するだけへ縮めない。
6. 取得前／部分取得／設置中／再訪／保存を、各対象の写真と通常操作で点検。

## 受渡口の導入とP01

承認済みの箱・鍵使用は導入操作で、30問に含めない。単独の丸印・二穴の返却札を得る。P01は他の返却札を得る独立した短問として設計し、導入をP01と数えて30の看板を維持しない。既存の受渡台・本・扉の配置を崩さず、必要な札入れを別の壁に配置する。

## 最初の全編用基準画像

- 帳場東面：受渡口東の開扉画像を参照。同じ机・油灯・本棚・額を維持。机の引出しP02、机上の保守鍵ケースP26。
- 校正室北面：受渡口北の戸口から見える乾燥棚を北面右へ保持。工房戸P07は北面左。棚下の工具箱P04には、取っ手でなく同心環の錠を実在させる。
- 搬出間西面：受渡窓の奥に見えている出口・左棚・右木箱を維持。裏口の型と最終組立台を実物として置く。

画像一枚の採否ではなく、全景・接写・操作後・隣室からの見え方で採否を決める。画像の候補と採用は台帳で区別し、最終配信には採用した実行素材だけを残す。
