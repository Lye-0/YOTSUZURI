# P14 断裁片の両面照合

破れた輪郭を合わせるジグソーではなく、直線で断裁された図面と三枚の細い余白を扱う。表の図面の線だけでは二候補、裏の試し刷りだけでも二候補が残る。双方の切り口がつながるのは一枚。表だけ合う別紙は北側に出入口があり、正しい図面の東側の出入口とは異なる場所を示す。誤った紙を選んでも同じ手掛かりが得られる構成にはしない。

`trimming.ts`の切り口データを`TrimInk.tsx`の印刷線と照合判定で共有。外側の白い余白を切り口へ向けた反転では合わない。各紙の表裏・上下と、添えた候補を保存する。紙を裏返すと切り口も反対側へ移る。

## 操作と所有

- 紙片へ触れると、その紙を大きく見て裏返し・上下回転ができる。
- 紙片を机上で図面の切り口へ動かす。既に別紙がある時は、先にそれを外す。
- ドラッグの代替として、観察を閉じた紙片を選択状態にし、切り口または図面へ触れて添えられる。添えた紙片へ触れると元の位置へ戻す。選択枠は傾斜する紙面内で細く潰さず、画面上で一定の太さにした。空いた机へ触れると選択解除。
- 添えた図面へ触れると二片を持ち出す。誤った組合せも持ち出せる。正解履歴で報酬を出す方式にしない。
- 手元で全体を返した向きも保存。持ち物で図面を選び、空いた台へ戻すと、その面を向けて置く。残っていた別の紙片の観察状態も維持する。
- 金属角当ては紙の隅へ置いて回収できる。位置合わせの補助であり、角当ての所持を正解や図面取得の条件にはしない。

## 実画面で見つかった問題

スマートフォンではドラッグ後のSVGタップに互換clickが来ない場合があったため、紙の通常操作に限りpointerの押し離しを直接受ける。さらに返却直後に操作対象が「持ち出す」へ変わると、遅れて来た互換clickで即座に再取得される問題が発生。`PhotoControl`の任意のdirectTouchモードで、コンポーネントの交換を跨いで同じタッチ列の互換clickを抑止する。マウスのpointerdownとキーボード・補助技術による操作は別に受ける。既存の機構は既定のclickモードを維持する。

ChromeのCSS matrix3dで紙面を投影すると、机上の細い印刷線が断続的に欠けた。影の除去、線の強化、印刷層をSVG画像一枚にまとめる方法では解消しなかった。紙面に合う平行四辺形の投影へ調整し、二次元matrixで描画すると解消した。紙の描画とポインターの逆変換は同じ座標を使う。`cssAffineProjection`は台形を黙って近似せず、四隅が条件を満たさなければ拒否する。他の写真機構の投影は変更しない。

## 検証と残件

PC1440×1000とタッチ390×844で、角当て設置→表だけ合う紙を添える→誤った図面を持ち出す→裏のずれを見る→返却→誤紙を外す→別紙を回転・裏返す→正しい紙を添える→取得→手元で表へ返す→角当てを回収→部屋へ戻る→再読込を確認。タッチは実touchStart/Move/End、マウスも写真座標で操作した。最終のtrim-*とtouch-trim-*を再撮影。debug/diagnostic/ink-plane名の画像は失敗・調査の資料で、採用の証拠ではない。

追加で、ドラッグを一度も使わずタップだけで誤紙の配置・取り外し、正紙の選択・配置、取得・返却・再読み込みを確認。互換clickで置いた直後に勝手に取得されないことも確認した。`touch-trim-selection-clear.png`は狭幅で選択状態を見分けられる最終の枠。
