# P15 逃げ溝と三つの留め

旧版の三本の独立した腕と固定順[1,2,0]は採用しない。戸と柱を跨ぐ蝶番付きの留め板に、一本の縦溝と中央だけ大きい逃げ口を置いた。三つの留めは頭が溝より大きく、中央まで動かした時だけ抜ける。

初期配置は上・中央・下。中央を抜いた後は、上→下でも下→上でも成立する。他の留めを追い越す移動は不可。抜いた物は受け皿に残り、中央が空いていれば一つずつ戻せる。全てを抜いてから板の自由端を開き、別操作で戸の丸い取っ手を回す。開扉は実際の現在状態から判定する。正解履歴だけでは通さない。

`keeper.ts`に位置3値と取り外し3値を保持。旧3値の途中データは位置と取り外し状態へ移行する。全景と接写は同じ金具・ピン・受け皿写真を参照。開いた板は柱側へ残り、戸上の取っ手は開いた戸の面へ移す。

## 不合格と修正

- 最初の板写真は自由な板まで四本のねじで固定していた。ねじを消した写真へ変更。
- 開いた板写真はガイドに三つの穴があり、連続スライドと矛盾していた。一本の連続溝へ変更。閉じた時と溝の位置がずれた候補も不採用にし、軸が一致した版へ再生成した。
- 受け皿の透過部品を重ねた表示では、手前の縁との重なりが不自然だった。1・2・3個が皿に収まった実写調の状態写真へ変更。3個版で小さな部品へ変わった候補は不採用にし、同じ寸法の既存2個へ3個目を足す編集を採用。
- タッチのドラッグはSVG内のg/rectへtouch-actionを指定するだけではブラウザにキャンセルされた。実際のpointercancelを記録し、操作中の外側SVGとstageにtouch-action:noneを指定して解消した。
- 新しい受け皿写真を操作時に初めて読むと、素早い次のドラッグが待機中に無効になった。接写へ入る時に少数の状態写真を先にdecodeし、連続操作中の待機をなくした。

## 検証

PC1440×1000で部屋から接写→中央抜き→上/下スライド→各引抜き→自由端→取っ手→全景→再読込を写真座標のマウス操作で確認。スマートフォン390×844では実touchStart/Move/Endで下側からの別順、途中保存、受け皿の接写、戻し入れ、再度引抜き、開扉まで確認。最終のtouch-keeper-*画像はこの成功後に撮り直した。pageerrorなし。

`keeper-wide-closed/open`は再読込まで待った最終状態。`keeper-initial/first-slide`は受け皿写真変更前の途中資料なので最終採用の証拠に使わない。
