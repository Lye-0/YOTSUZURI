# 終盤の写真機構の試作

計画10・12・13が要求する終盤の試作を、全室展開と別に検証する。まだ本編全体に到達可能な終盤を実装済みと扱わない。

## 鍵

六枚歯を同じ実写の軸・ねじ付き保持部・伸縮する金属片で構成。保持部は動かず、刃の突出量が四段階に変わる。数字や六桁の入力欄を通常表示しない。手元の観察と持ち物欄は同じ配列から同じ形を描く。全体を先に表示し、虫眼鏡で歯だけを拡大できる。

鍵を差す前に本や模型の既読を要求しない。誤った鍵も差せる。回らなければ抜いて修正できる。差込中は手元から除き、差した時点の歯を保存する。本を後で変えても挿入中の鍵が勝手に変わらない。

## P27 断面模型

現物の三つの下つまみが下の金属片を持ち上げる。金色の受け側の長さは[2,1,4]。合計が五単位なら、上の鉄片との接点が実物の横目地へ揃う。目地の場所は写真内のy325、基準底はy525、単位40px。数値をプレイヤー画面には印刷しない。

揃えただけでは取っ手は動かず、自分で引く。間違った状態では引けない。調整し直すと取っ手の試行状態を解除する。取っ手の差分だけを合成し、筐体や机の木目を別の生成結果へ丸ごと切り替えない。

開発時のみ`remake.html?lab=cutaway`で独立検証できる。通常のゲームに開発用メニューを増やさない。production buildではラボ分岐を除外する。

PCで写真上のつまみを[3,4,1]へ操作し、三接点の目地への整列を目視。取っ手の引出しを確認した。画像は研究`remake/qa/cutaway-aligned.png`、`cutaway-open.png`。引いた時に先端が切れたため、接写範囲を1292:760へ拡張した。拡張後の画面とタッチは再検証が必要。

## P22・P30の共通の束

未実装の設計契約。六束を横へ六枚並べた盤面に置き換えず、一冊に積まれた紙の端面として描く。写真の端面帯を各束に対応させ、同じ帯を並び替えて同一性を保持する。生成物は六束と指定しても五束になる、透過に見える市松を不透明なRGBへ焼き込む場合があるため、数と実際のalphaを検査する。

束の基礎厚みはID順[2,2,1,1,3,4]。正しい順[3,0,5,1,4,2]に並び、位置1・4へ白紙を戻すと、厚みは[1,3,4,2,4,1]になる。これを六桁として印刷せず、物の厚み・端面の位置関係として示す。鍵側は模型の補い合う関係から[4,2,1,3,1,4]を本人が作る。

小口の絵は修復室の隠し戸と同じ幾何を基に分割する。正解フラグで完成絵へ交換しない。向き・順・白紙が違えば、同じ断片の位置から不連続が生じる。知っている人が先に現場の戸を開けてもよい。

この部分は写真素材と表示の試作中で、合格済みではない。

### 実物状態への移行と試作結果

本は`World.book`に束順・白紙位置・基準側・開閉・圧締を持つ。P22で揃えた束を持ち運んでも順は残る。一方、P23等の過去の解答値を最終組立へ自動転記しない。最後の場面で現在置いた白紙・向き・締め具を確認し、過去に正解したフラグだけでは本を完成させない。

`remake.html?lab=foreedge`を開発専用試作へ追加。六束の端面写真を前・側面へ同じ順で投影し、絵は各束の同じ断片から作る。PCの写真座標へのクリックと、390×844の独立タッチ環境での拡大操作で[3,0,5,1,4,2]に入れ替え、連続した絵が出ることを確認した。`touch-foreedge-detail.png`、`touch-foreedge-assembled.png`に記録した。タッチの青い標準ハイライトはその後抑止。

薄い束の入力を広げるため、同じ写真を端面へ寄せる拡大表示を追加。別の木箱や汎用盤面へ切り替えない。紙の葉を読みやすくする素材更新と、接合部の質感の最終点検は継続する。ラボでの成立を本編の到達性・全景との整合・最終復元UIの完成と混同しない。

## 読込中の整合

場面の主写真だけでなく、部品差分・持ち物・紙の単体写真を一組としてdecodeする。揃うまでは前の表示状態を保持し、別の部屋の部品だけが先に重ならない。帳場全景、箱の解錠差分をそれぞれネットワークで保留し、保留中の写真一覧と解放後の一覧で混在しないことを検証した。画面の状態と保存状態を区別し、保存は現在の操作結果を記録する。
