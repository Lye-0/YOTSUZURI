# 謎の接続と製本工程の修正

2026-09-23。監査計画 51_CAMPAIGN_REVIEW_PLAN.md に基づく変更。

## 実装した接続

- 印刷 → 保守戸: 白地の幅を六つの高さで読む。紙の I〜VI と幅の物差しを、保守戸の六段の留めに対応させた。設定は windowPoints から実際の断面幅を計算して導く。完成見本は上部だけ残った断片とし、全六段の答えを公開しない。三つの既存の抜き留めに加えて六段の留めも合わせる必要がある。資料の既読フラグは使わない。
- 小口の絵 → 隠し扉: 扉の絵の隣に六段の機構の図を描き、覆いの下に同じ可動機構を設置。場所の三択だけでは扉は開かない。正しい全設定で取っ手を動かすと解放する。
- 復元本 → 保守鍵: ケースから得た鍵は歯が未固定。本を閉じて綴じ、押さえ板を上げ、手前に移し、本の実際の六段の厚みを使って歯を合わせ、固定する。固定後は歯の横に金具を表示。未固定鍵は数値が正しくても回らない。誤った本でも可動範囲内なら固定可能だが、その寸法が扉と合わなければ開かない。固定を緩めて再加工できる。正解の束IDや既読フラグを鍵固定の条件には使わない。

白地の幅は [160,256,214,256,256,0]、尺度 [0,160,214,256] に対する設定が [1,3,2,3,3,0]。小口の図は [2,0,3,1,2,1]。双方とも入力ごとの正誤は教えず、実際に板／戸を動かす際に全体を判定する。

## 製本と表示

- 白紙の供給元を実物画像と用途名で表示し、束へドラッグして挿入。キーボード／クリックでは供給元を選び挿入先を選ぶ方法も維持。
- 束はドラッグで並べ替える。白紙は挿入済みの束に付随して動く。
- 紙標本と紙束の対応を、順序を直接答えにしない共通の印（○◇＋∥△□）で表示。○と△の欠損の痕跡と補充先を照合できる。
- 拡大カメラを紙束全体の中心へ修正。名称付きの閉じる、載せ替え、裏返す、圧締、縫合、鍵固定操作を同じ画面で行える。
- 糸不足、針不足、広がった束、未設置、カム不一致、圧締前を別々の案内にする。
- 狭幅は縦方向の余白を確保し、紙束と白紙供給元と操作列の重なりを軽減。
- 印刷の入れ子SVGが親の寸法で拡大されていた点を修正。900×400の接触面を明示し、測定線と実際の白地の位置・幅を一致させた。
- P2/P3/P26 の数字を崩した後は、過去の solved 履歴だけで開かないよう現在値でも判定。

## セーブと別解

既に開いた保守戸、隠し戸、開錠済みの出口を閉ざさない。旧保存で本と鍵まで完成していた場合は固定済みとして移行する。移行済み印を保存し、現行プレイで固定を緩めた状態を過去の完成履歴だけで再固定しない。

本の重さを比べる行為は対象の本を見つける補助、写しと二原型は本の読み方向を見つける補助として残す。これらの「見た・量った」履歴を要求する通行条件は追加しない。棚を図面なしで解くことや、既に原理を知って模型を省略することも許容する。先の計画の選択肢のうち、全てを必須フラグにするのでなく、最終物の成立に必要な実作業と情報の補助を分ける方針を採用した。
