## 結論と確認範囲

現在の問題は個別の画像・ボタンだけではない。手掛かりを作る工程が次の仕掛けの判断材料として接続されていない、長い工程の出口が三択になっている、本の復元が最終的な鍵の成立と切り離されている、という構造上の不足がある。個別UIの修正を続ける前に依存関係を改める。

全11部屋の移動条件と全30仕掛けの入力・出力・後続用途をコードから追跡。関連する画像・操作コンポーネント、ユーザー提供画像、既存の制作資料・テストも照合した。8件の確認用テストで抜け道・誤案内を再現。既存155テストと合わせて163件通過したが、これは設計の妥当性を証明しない。三枚の扉を小口未完成で開けること自体を、既存テストが期待していた。

今回は計画のみ。ゲームのコード・画像・ユーザーのセーブは変更しない。全画面の新規目視通しプレイ、初見プレイ評価は未実施。したがって、残存する全ての視覚的不具合が除去できるという結論ではない。

repository-memory は agent-knowledge が存在せず非適用。既存の docs/remake に計画を保存する。

## 8件の再現の意味

1. 最初から受渡口→帳場→搬出間で終了。ケース番号1927と鍵歯[4,2,1,3,1,4]を既知として入力。初見で簡単に当たるという意味ではなく、実際の経路・通常のActionだけで本の工程を全て省略できる証拠。
2. 印刷物・道具なしで保守戸の留めを外して開ける。
3. 小口未完成・支持具なしで中央の扉を開け原型庫へ進む。
4. 一度も量らず帯を外して対象本の背を開け、木片を取る。
5. 四片の枠を組む前に返却記録を取れる。これ自体を不具合としないが、枠組立が記録取得の前提だという想定は誤り。
6. 圧締済みで糸がないときも「締め具で押さえる」と案内する。
7. 本の成立は束順と挿入位置で決まり、紙標本の観察・白紙につけた記録とは独立。
8. ケースの数字を正解から0000へ変えても開く。

確認用コードは研究フォルダー qa/campaign-audit-20260922.test.ts.txt に退避。src/remake に一時配置して実行した。抜け道を恒久的な期待動作としてテストへ固定しないため、ゲーム側には残さない。

## 修正の設計方針

- 手掛かりを見たフラグだけで通行・操作を禁止しない。
- 情報を当てること自体を完全には防げない。目標は「三回試すだけで長い工程が消える」ような接続をなくすこと。
- 独立に形を観察して解く別解と、使い道のない長い工程を区別する。
- 間違った紙・束も扱え、実物の不一致が見え、戻して修正できる状態を保つ。
- 同じ物理結果なら受け入れる。表裏、同じ厚みの等価な配置などを、隠れた正解IDだけで拒否しない。
- 説明を増やす前に、物体の同一性、配置、状態変化、対象と操作の関係を直す。

## 実装順序と具体案

### 第1段階: 前半〜隠し扉の情報接続を確定

P10/P12/P15を一つの問題として再設計する。保守戸は白い輪郭の切り欠きから複数の解放位置を読む構造にする。単に三つの留めを同じ位置へ運ぶ現仕様は撤去。印刷と扉に共通の形・向きの基準を実物で表示する。

現在の完成見本は解答を丸ごと公開しているため採用し続けない。欠損した見本に変更する案を第一候補とする。ただし、残した部分だけで版選びの根拠があり、留めの全設定は分からないことを、四枚の版と全組合せの描画で検証してから採用する。これが成立しなければ、見本ではなく試し刷りを比較・交換する課題へ簡素化する。画像を欠かすだけで済んだとはしない。

P22の小口絵は扉の外形だけでなく、留め具の位置・向きを含む一枚の作業図にする。三枚の扉から場所を選んでも、それだけでは解放されない実物を描く。見えていない操作点を探すピクセル探しにはしない。仕掛け全体を設定して最後に取っ手を引く形にし、各段の成功表示を積み上げるだけの総当たりも避ける。

**完了条件:** 見本から版を選ぶ根拠を説明でき、刷り紙から保守戸の操作を導ける。小口の絵から対象と解放設定を導ける。三候補を一度ずつ触るだけでは解けない。どちらも資料を読んだ履歴の有無では判定しない。

### 第2段階: 製本が最終的な鍵作りになる構造へ

ケースから得るものは六枚歯を保持する未固定の部品にする。復元本の六段の厚みを治具として使い、圧締機で歯を合わせて固定する工程を作る。本を復元する意味と、固定されていない鍵では力を伝えられない理由を画像・可動部で表現する。現在の「自由に歯をクリックして完成鍵にできる」経路を置換する。

写し・現扉・二原型の照合結果は、この固定具の肩・穴・向きの選択に使う。二択の答えを得て終わる資料にしない。断面模型は歯と受け側の高さが相補的になる原理を実機と同じ寸法・向きで示す。

ここは新しい物理表現が必要なため、先に静止画と操作途中の模型で成立性を確認する。「正しく製本したフラグがないと鍵が回らない」とだけ追加する実装はしない。等価な形で加工できる組合せは隠れた紙IDで拒否しない。必要なら最終目標として本の修復・返却も世界内で明示し、開錠と修復の評価を分ける。

**完了条件:** 未加工部品はそのまま開錠に使えない。正しい紙補充・閉じ方・固定状態から実際に鍵ができる。誤った加工は寸法不一致として確認・解除・再加工できる。数値だけを知っていても物として必要な組立は残る。

### 第3段階: 白紙補充と製本UIを組み直す

二枚の白紙は「欠けた葉を補う紙」と分かる折り・大きさ・置き場にする。標本で見た切断跡と、実際の束の欠損箇所を同じ特徴で照合できるようにする。並べ替えで順番が変わっても同じ束だと分かる控えめな識別を付ける。II/Vだけを機械的に表示して答えを配る方式にはしない。

白紙をつかんで対象の束へ動かすと、その束が開き、内側に挿入され、厚みが増える。取り出す動作も同じ場所から行う。束の並べ替えは直接ドラッグ。閉じる・全体を裏返す・押さえる・綴じるは、それぞれ対象のそばの必要最小限の名称付き操作にする。

拡大から全景へ戻らず必要な操作を続けられる構成を、紙束・圧締機・白紙置場の一画面で設計する。状態は選択、移動中、設置済み、固定済み、縫合済みを見分けられるようにする。

**完了条件:** 初見の人が二枚の白紙の用途と挿入先を実物から説明できる。アイコンの意味を質問せずに操作できる。間違った挿入・順序・縫合から材料を失わず復旧できる。

### 第4段階: 判定・案内・保存の整合を一括修正

P2/P3/P26の履歴と現在の錠の状態を分離。製本のエラーは実際に不足している条件に限定。過去に解いたが現在崩した状態、既存の誤った刷り紙と新しい完成紙の交換、別の場所に置いた工具などをヒントへ反映する。

紙の印刷面／見る面／回転／投影座標を共通モデルで扱い、表示が同じなのに判定が違う再発を防ぐ。画像は接触面の幾何と照合する。白紙も標本番号、束ID、現在の位置を混同しない。

既存セーブは所持品・紙の履歴を維持する。新機構へ移行する際、既に開いた通路を一方的に閉じて利用者を閉じ込めない。未加工鍵・旧完成鍵・修復途中の本の移行規則を実装前に明文化する。新規セーブの設計と旧セーブ救済を別々に試す。

### 第5段階: 全編確認と初見評価

1. 各仕掛けの「得る情報→使う先」を図とテストで固定する。
2. 全30仕掛けについて、実際の画面で全景→接写→操作中→成功／失敗→持ち帰り→再訪を確認する。
3. 三択総当たり、全本の背を調べる、正解番号の先行入力、資料未取得、逆順の素材設置、誤った紙、紙の裏面、保存・再開を試す。
4. 本の白紙補充から圧締・縫合・鍵加工・出口まで、正解経路と一度間違えて戻す経路を通す。
5. 解法を知らない評価者に画像と通常UIだけで試してもらう。内部名や正解を含むアクセシビリティ名で誘導しない。分かった根拠と詰まった場所を記録する。
6. PCと390px級のタッチで、操作枠・スクロール・表示サイズ・動きの軽減設定を確認する。

## 優先順位と今回の境界

優先順位は、第1・第2段階の設計確定 → 第3段階の画面試作 → 第4段階を伴う実装 → 第5段階の通し確認。見た目だけを先に作り込んでから用途を考える順序には戻さない。

本資料の提案、とくに鍵の固定工程と保守戸の構造は未実装であり、物理表現の試作確認が必要。今回変更するのは監査記録と計画のみ。
