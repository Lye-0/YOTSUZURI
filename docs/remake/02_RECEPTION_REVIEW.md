# 受渡口の代表実装と確認

2026-09-21。ユーザーは確認版 `/remake.html` の「四方向の視点移動・箱や本への接写・持ち物の選択と使用」について、「はい　問題ありません」と回答した。この方式の全室展開へ進む。全編の完成や謎の難易度への承認とは扱わない。

## 実装した代表の一巡

- 固定点から四方向を90度ずつ見回す。左右は写真中央、接写の戻るは下中央。
- 箱の写真上で留め金を上げ、蓋を開け、鍵と札を別々に拾う。
- 一部取得後も残りは箱に見える。全景に戻っても同じ状態。
- 持ち物を選んで鍵穴へ差し、キーを回し、取っ手から戸を開く。鍵の所在は手元から錠へ移る。
- 黒い本と壁の紙を実物として調べられる。本の開閉は全景にも残る。
- 採用素材25枚。原本を研究フォルダの `remake/masters/`、実行用を `public/remake/`、台帳を本ディレクトリへ保存。

## 確認の証拠

研究フォルダ `remake/qa/` にPC1440×1000とタッチエミュレーション390×844の画面を保存。写真の実物位置から座標を選び、mouse.click / touchscreen.tapで箱、留め金、蓋、鍵、札、鍵穴、ノブを操作した。正解状態の注入はしていない。

全景→接写→片方取得→全景→再訪→残り取得→使用→再読込→開扉が成立。間違った札を鍵穴へ使っても消費されず、差した鍵の状態は再読込後も保持した。6件の新規状態テストを実行。旧版16件は別物であり、新版の全編検証には数えない。

通常画面の部屋名一覧、問題名の見出し、汎用答え合わせ、常設説明文を撤去。設定と任意ヒントのみ文章を使う。資料を読む表示と設置物の接写は別の画角を選ぶ。

## 修正した画像上の不整合

- 西面の床板が北面と同方向だったため、90度回った向きへ再制作。
- 錠の側へ誤って出た蝶番を除去。
- 表戸の鎖をガラスの外側へ置き、手前の桟とガラスで遮蔽する全景・接写へ再制作。
- 案内紙の縦横比と図の出入口を修正し、全景にも同じ図を反映。
- 取得・留め金・鍵の差分は対象の位置へ限定し、背景の微小な生成差を持ち込まない。

## 限界と残作業

これは代表実装。10室と本編30問の再構築はこれから展開する。受渡口の鍵取得は導入操作であり独立問題数に数えない。旧版の問題数をそのまま新作の成立数としない。

タッチはブラウザのエミュレーションであり実機ではない。固定景色を保持するため縦長端末では余白が大きく、横向きを案内する。初見の難易度と時間は未計測。
