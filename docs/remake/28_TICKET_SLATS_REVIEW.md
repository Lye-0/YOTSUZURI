# 札入れの「見て判断できない重なり」の修正

2026-09-22。ユーザーの画像では、旧木札が同じ平面の切り欠きに見えた。コードで指定した抜け順を説明するだけでは、手前へ抜く動作や、隣の板に押さえられている理由を読めなかった。前回の通し操作成功を、仕組みの伝わり方の合格に広げた判断を改める。

## 変更

- 切り欠きの四枚を、丸い引き手のある四枚の木板に置き換えた。
- 金具は二つのねじがある側だけを自分の板へ固定し、ねじのない舌が隣の板の手前にかぶさる。段差、厚み、接触影を写真で表現。
- 一番上の金具は二枚目の右側へ、二枚目の金具は三枚目の左側へ、一番下の金具は三枚目の右側へ延びる。
- 描画位置と深さを `ticketSlats.ts` にまとめた。抜ける条件はその金具と板の重なりから算出し、別の暗黙の順序表と二重管理しない。
- 引っ掛かった板は小さく動いて戻り、抜ける板は金具ごと手前へ動いて外れる。動きを抑える設定も尊重する。
- 全景、接写、途中状態、再訪、観察記録で同じ写真部品を使う。保存済みの四枚の状態と取得済みの札は引き継ぐ。
- 札の穴が最初から隙間に露出しないよう、札を板の後ろへ収め直した。旧 `p01-case.webp` は使用終了して削除。

## 写真

内蔵 image_gen で生成。採用した写真は `public/remake/parts/ticket/` の `slat-0.webp`〜`slat-3.webp` と `keeper.webp`。木目が異なる四枚の板、引き手、上側にねじがある段付き金具を生成し、実アルファ付きの写真を採用した。ケースの写真は既存の同一物を維持。

正確なプロンプトと生成元は、研究ディレクトリ `4_YOTSUZURI/remake/generation-metadata/ticket-repair.json`。原画は同研究ディレクトリの `masters/parts/ticket/`。本番側には採用品だけを置く。

## 検証と限界

PC1440×1000とtouch390×844で、最初の二枚目・三枚目が外れないこと、上から開始／下から開始、途中再読込、全景への戻り、札二枚の個別取得と空状態を実座標で確認。ねじと自由端の重なりは両サイズの接写で目視した。板の中心だけでなく端寄りも押した。残るもう一つの有効順はEnter操作で確認。

実クリック後のアニメーションも計測し、引っ掛かる場合は平行移動して戻ること、外れる場合は手前へ拡大して動くことを確認した。純粋規則の検証は有効な三通りすべてと、片側の金具だけ残る場合、途中保存を含む。

これは作者による確認であり、初見の人が迷わないと保証する試遊結果ではない。UI Evolveの representative-verification / action-relationships を参照し、既存の「操作成功と行為の理解を分ける」基準を今回の採否へ適用した。同じ一般則を重複してグローバルスキルへ追加する必要はないと判断し、具体的な修正根拠を本記録へ残した。
