# 序盤の実装・目視確認（継続中）

全編の完了ではない。ユーザーの追加確認を待たず制作を継続する。

## 写真と機構の整合

- P01: 写真の木札は0→1、1と3→2という干渉関係を持つ。0と3はどちらを先に外してもよい。旧版の単一固定順を強制しない。収納カードを縦向きにし、上端を木札で押さえ、下端を前板で隠す。札を外す前からカード全体が露出する矛盾を修正した。
- P01の壁面は部屋写真で再生成し、部品だけを同じ位置へ重ねる。接写の背景に別の部屋のカウンターが現れる不整合も除いた。
- P04: 二つの環を実写部品として回転。途中・正解・開蓋で向きを保持。一度正しく合わせても、再びずらしたら蓋が開かない。ナイフ・鏡は独立取得で、全景と接写の残品を共有。
- P05: 見本を定規へ移すとトレーから同じ見本を消す。破断端をゼロとして扱わず、残る目盛の差で六目盛の間隔を読む。ナイフで同じ長さを下の紙から切り出す。誤った長さも物として保持して交換可能。刷り機への適合は取得フラグではなく実際の長さで判定する。
- P06: 三枚の紙は個別に裏返せる。印・切欠き・表裏を同じ紙の変換として描き、再訪時にも保存。全景にも現在の向きを描く。
- P07: 手元の二枚の紙は表裏／折る／重ねる／めくる／取り分ける操作を持つ。八頁の対応は共通の面付け計算から導く。印が線上にある頁と線から外れた頁を区別し、表紙の傷と頁をまたぐ線で順番を判断する。錠は既読なしで入力可能。

## 実行した範囲

PC 1440×1000で写真の座標へクリック。P01は初期に三枚目が動かないこと、下→上→二枚目→三枚目で外せること、菱形の札だけ取得した状態で再読み込みして三日月の札が残ることを確認。P04は環を回し、開蓋、ナイフだけ取得、全景へ戻り鏡が残ることを目視した。

P05は四枚目の見本を定規へ移し、ナイフを選択して切り出し、六目盛の位置決め片を所持。重複した見本、トレーからはみ出す紙、透過余白で紙が細くなる表示を修正。P06は中央の紙を返して全景へ戻り、状態を保持。

P07は写真上の折り目と紙の端をクリックし、二枚を折り、片方をドラッグして重ね、実際の頁端でめくるところまで目視。閉じた紙が横折りに見える画像を縦の折り目の写真へ交換した。工房戸の押し金へ菱形・丸・三日月・二本線を入力し、取っ手で開扉、全景で活字室を見通すことを確認。

390×844の独立タッチ環境で開始→受渡口南→札入れ→4枚の除去→菱形だけ取得をtouchscreen.tapで実行。画面全体の縦横はみ出しなし。収納の接写は対象に合う835:720へ変更し、木札を読める寸法を確保した。持ち物欄に出た不要な縦スクロールを修正。実機試験ではない。

証拠は研究フォルダー`remake/qa/`の`reception-case-fresh.png`、`reception-case-close.png`、`touch-case-start.png`、`touch-case-one-card.png`。後二枚は縦スクロールと回転案内の修正直前。
