# 検証記録 — 2026-09-21

## 実施した確認

| 対象 | 方法・結果 |
| --- | --- |
| 全体の進行 | Playwright MCP / Chrome。新規状態から30の描画済み操作画面を経由し、実際に取得・移動して終幕へ到達。保存状態の注入なし。 |
| 自動検証 | Vitest 16件。全経路、別室操作の拒否、取る前の開封、重複防止、材料、棚の衝突、途中保存、不正形式、最終鍵。 |
| 解の図示 | 刷りの96通り、折りの8通り、鍵の4096通りを検証。紙の窓から読む4つの保守位置も実画面で確認。 |
| 目視 | 11室の全景、30仕掛けの操作前後、主要な取得後・開扉の写真を撮影して確認。詳細画面の一覧と個別拡大を併用。 |
| 小画面 | 390×844で30箇所を巡回。札・天秤・版・封筒・透かしの横あふれを修正。再検証で dialog の横あふれ0件、最終退出操作に到達。 |
| 保存再開 | 中盤でページをリロードして継続。JSONのダウンロードと再読込を操作。壊れたJSONを読み込んでも30箇所分の進行を保持。 |
| 本番ビルド | Edgeで4199番のプレビューを開き、開始・札の操作・Escape・リロードを実行。途中状態の保持、画像欠落0、エラー画面0を確認。 |
| 素材 | 採用WebP 33枚、約6.97MiB。台帳未登録0枚。環・拡大鏡・糸の透過維持を検証。候補PNGはリポジトリに含めない。 |

通し検証の一部は標準のPlaywrightクリック、長い反復部分は描画要素のDOMクリックを使った。後者も本番のReactイベントと状態管理を経由するが、ポインターの命中検証の代替とはしない。対象位置は部屋写真の実寸表示で別途確認した。

## 修正した主な不整合

- 開いた収納・回収済みの版や部材が全景に残る問題を状態写真の局所差分で修正。
- 校正箱の数字が罫線を合わせずにそのまま読める状態を修正。連続する線から読む段を決める。
- 版の面が空白だった表示、見当の向き、写しの反転、反射片と光線の向きを修正。
- 紙の表裏・透かしの見本と、選択肢の図示を同じ構成要素へ統一。
- 折りの異なる状態を一律の誤配置で描く処理を、入れ子と表裏から頁順を求める処理へ変更。
- 刷り紙と旧図を重ねることで、書架の留めの向きが分かる連携を追加。
- 実物と説明資料で重複していた「小口の見本」の操作名を区別。
